# 使用说明（中文）

当前适配多邻国 6.105.2（2497）和 6.106.3（2501）的 ARM64 构建。**只需安装一个 ChessPilot 合包 APK**，包名 `com.chessassist`，包含 API 102 模块、引擎、服务和状态页。两版的实际 APK 均已通过接口核验，新版真机联动待验证。

覆盖安装需同一签名，原伴侣设置可沿用；独立旧模块须在框架中停用。保留 0.5.1 极限思考修复。使用电脑算力时，同时更新并重启 `pc/pc_engine.py`。

> 英文技术文档见 `README.md` / `docs/REVERSE_ENGINEERING.md`。注意 README 里早期的
> ContentProvider 轮询桥已废弃，当前是回环 TCP 桥（见下文“架构”）。

## 一、安装启用（只需做一次）

1. 手机已 root，且使用支持 **libxposed API 102** 的框架。旧版 LSPosed 不能加载本版。
2. 安装合包 APK，打开点「启动引擎服务」（允许通知；悬浮窗按需授权，只影响备用横幅）。
3. 框架管理器中停用原独立模块，启用包名为 `com.chessassist` 的 ChessPilot → 作用域只勾 `com.duolingo` → **首次迁移时结束多邻国运行再重开**。
4. 打开多邻国下棋。App 状态页的 `Hook 连接` 应变成“已连接”，走一步出一条 `published:`，
   1 秒左右棋盘上出现黄色原生箭头。

ChessPilot 不需要单独的 root 授权。以后更新 API 102 合包会请求自动热重载；控制页也可手动重试已过期的模块。热重载失败/不支持时重开多邻国；更新 APK 后如引擎服务停止，重新启动服务。详细限制和验收步骤见 [API102_CPU.md](API102_CPU.md)。

## 二、状态页怎么看（App 主界面，每秒刷新，页面可上下滚）

主界面开关收拢到「功能设置」一组（自动走棋/狂暴模式/极限思考一排，默认展开）；
滑杆和算力后端留在「高级设置」里。

| 行 | 含义 |
|---|---|
| 引擎状态 | 运行中 / 启动中… / 已停止 / 启动失败 |
| Hook 连接 | 显示桥接连接、手机上实际安装的多邻国版本，以及棋盘接口的匹配结果。 |
| 模块状态 | 框架名称/API 版本、热重载结果；与棋局 socket 连接是不同状态 |
| 引擎 | 实际线程/Hash/深度及 CPU 路径：`NEON DotProd` 或 `ARMv8 NEON` |
| NNUE | 已加载的神经网络（SF19 起应为 `embedded nn-1a298aa575a0.nnue`，单 V16 网） |
| 当前 FEN | 最后一个收到的局面 |
| 执棋颜色 | 人机和真人对局显示会话分配的颜色。执黑时小棋盘将黑方放在下方。 |
| 最佳招法 | 引擎给上一个局面的招（带我方胜率，杀棋会标 Mx） |
| 对局结束 | 显示已取得的胜负与原因，例如「胜利 · 超时」。本局停止自动走棋，下一局沿用开关设置 |
| 思考设置 | 当前生效的思考时间/固定深度 |
| 自动走棋 | 开（450ms）/ 关（与开关和间隔同步） |
| 极限思考 | 预计算中 / 预测 → 应招及深度（已备好）/ 命中及取用耗时 |
| 最近错误 | 有则处理，无则忽略 |
| 最近事件 | 带时间的启动/连接/招法流水 |

## 二点五、三个新功能

- **胜率显示**：横幅和状态页在最佳招下多一行 `我方胜率xx%`（UCI cp 分经 logistic 换算，
  按你的颜色折算；拿不到颜色时回退显示黑/白胜率；杀棋显示 `我方M3`/`对方M2` 样式）。
- **常驻状态横幅**：深底圆角，可拖动（位置自动记住），跟着引擎状态走：
  手动己方回合 `等待走棋中…/正在计算…` → `推荐：e2e4/我方胜率xx%`；
  自动模式 `自动走棋中…/正在计算…` → `自动走棋中：e2e4/我方胜率xx%`，标题旁有转圈动画；
  对方回合 `等待对手走棋…`（第二行保留上步结论）。胜率按三档变色（≥60 绿/40~60 黄/<40 红）。
  右侧 `走棋` 按钮：手动有招可点，自动模式置灰显 `自动`；横幅本体不可点，不挡误触。
  自动工作时标题旁有圆弧转圈（自绘 View＋属性动画；试过系统 ProgressBar，其
  indeterminate 在悬浮窗里不渲染，ASCII 逐帧跳又太抖，特此记录别回退）。
  授权过悬浮窗即显示，无需其他操作。
- **思考设置**：`思考时间 100~3000ms`（默认 700，10 分钟 PvP 建议 1500~2000）；
  `固定深度 0~30 层`，0 表示按时间思考，非 0 则忽略时间按层搜
  （手机上 22 层以上会很慢，实测深度 26 约 19 秒；固定深度无时间管理，长对局慎用）。
  两项即时生效、自动保存，重启后保持。
- **自动走棋开关**：默认关闭（ToS 封号风险）。打开后，引擎只在“算出招的 FEN == 当前棋盘”
  时才点格子，过期招直接丢弃。开关自动保存。
  注意：走棋靠模拟点按棋盘 Rive 视图，要求棋盘可见；切后台/锁屏时不要开。
- **狂暴模式**（高级设置里，默认关）：线程拉满（全部核心）+ 大内存（512MB 或
  总内存/10 取小，保底 128），普通模式是 `核心数-2`（上限 4）+ 128MB。
  切换即重启引擎（1~2 秒空档，局中可切）。满载发热大，降频反而更弱——烫手就关，
  思考时间建议≥1500ms（共用滑杆）。悬浮窗狂暴时带红框 + `狂暴` 角标，普通是纯黑，
  一眼区分。预期相对 700ms/4线/64MB 约 +100~150 分；
  对面若是桌面多线程长考挂，依然打不过，看深度认栽。
- **深度读数**（诊断仪）：横幅第二行 `深度22 · …` 与状态页 `引擎：狂暴 · 8线 · 512MB ·
  深度23`。长考下深度常年个位数 = 引擎被限流/过热降频，先查模式和散热；
  深度 22+ 还连跪 = 对面大概率也是挂。
- **极限思考 Ponder**（功能设置里，默认关）：对手回合提前搜索预测局面下的我方应招，
  并缓存每轮已完成的搜索结果。例如悬浮窗显示
  `预测 e7e5 → 应招 g1f3 · 深度18（已备好，继续深算）`；深度随搜索更新。
  命中后直接复用，推荐行标注 `预测命中`，状态页和事件记录预测招、应招、深度及取用耗时。
  未命中则丢弃并正常搜索；命中校验同时检查历史和目标 FEN，避免碰巧最后一步相同而误用。
  某些课程不提供历史时，用引擎给出的完整目标 FEN 核对。
  关闭开关、重启引擎或新开局会取消旧任务，迟到结果不能覆盖新一轮。
  棋盘灰箭仍只表示预测的对手走法；预备应招显示在文字中，尚未命中时不会自动落子。
  Stockfish 在 ponder 状态下会暂缓输出 `bestmove`，时间上限也不能当成普通搜索计时。
  因此从已完成的 `info ... pv` 提取预备应招；需要最终结果时用 `stop` 结束已有搜索，
  不在命中后再等一轮完整预算。已完成任务的结果会保留，不会被等待循环反复重开。
  本地和电脑端均使用独立进程隔离主分析与预计算。对手若在预计算开始前就落子，
  则仍走正常搜索；已算出的深度不代表真机端到端延迟，需结合实际对局核验。
- **FEN 双保险**：发招前结构 + 子力数双校验（单王、每方 ≤16 子、兵 ≤8、无底线兵），
  坏局面直接拒收。SF19 对非法输入是杀进程，之前一个手写多兵 FEN 把引擎打进
  crash-loop 就是这么查出来的。
- **自动升变**：自动走棋和横幅的「走棋」按钮都支持升后、车、象、马。棋盘接受兵的
  落点后，ChessPilot 使用原生选择器的回调提交引擎指定的棋子，例如 `e7e8n` 会升为马。
  若当前版本缺少可识别的选子接口或落子未确认，横幅会提示需要手动升变的棋子。
- **走棋间隔**：`走棋间隔 150~1500ms`（默认 450），每步再 ±20% 随机浮动，落点也在格内随机偏移、
  按压 150~230ms——太快会被棋盘吞掉导致棋子弹回。走完会核对招法是否落子，
  没落上且棋盘没变就自动补点一次（日志 `autoplay performed ... attempt 2`）。
  间隔同样自动保存，并随每条招法下发到对局端。
- **连击保护**：同一招连点走棋按钮时，在途的链路没走完之前重复点击直接忽略
  （日志 `ignoring duplicate tap`），不会两套手势交错把棋子点飞。
- **横幅拖动**：纯偏移拖拽（不碰 gravity，无跳变），松手位置连同 gravity 一起记住，
  下次原位恢复；拖动阈值内松手不影响按钮点击。

## 三、故障排查对照表

| 现象 | 原因 / 做法 |
|---|---|
| `Hook 连接：未连接` | ① 模块没启用/没勾多邻国/没重启后重开多邻国；② 还没进棋局（不进对局就没有局面）；③ 多邻国升级导致类名变化（见“多邻国升级”） |
| 框架看不到新模块 / API 版本不足 | 升级到明确支持 libxposed API 102 的框架；确认启用的是包名 `com.chessassist` 的合包 |
| 热重载失败或一直没有新局面 | 结束多邻国运行再重开；同时检查 ChessPilot 引擎服务是否因 APK 更新而停止 |
| 白方开局显示“等待对手走棋” | 两处跨局残留都已清：钩子侧开局重置 userColor，对局端 STARTPOS 跃迁重置去重记忆（之前连打两把开局，第二把必哑火——伪钩子连发两次开局验证通过）。若复现，把 LSPosed 日志里 `published:` 那行（带 `user=`）贴出来 |
| 进对局多邻国闪退 | 已修（画箭头必须在主线程）。若复现，抓 tombstone 看崩溃线程名是不是 `duo-chess-bridg` |
| 点启动 logcat 没日志 | MIUI 会吞 release 包的 INFO/DEBUG（E 可见），属系统行为；看 App 内状态页即可。非要看 logcat 请用 debug 包 |
| 点停止有条 E 日志 | 老版本把正常关机打成 error，现版本安静退出 |
| 箭头只第一步有效、之后一直转 | 老版本同 FEN 重报 + 去重过期 bug，现版本同 FEN 只报一次、画过不再画 |
| 引擎反复重启、30 秒退避 | 大概率 NNUE 文件损坏/截断（见下），或 `libstockfish.so` 缺失 |
| `bridge waiting for companion` 每 10 秒一条 | 正常：伴侣服务没启动，点「启动引擎服务」即可 |
| 对局中途卡死（横幅定住不动） | **已修复**：根因是动画中途碰 Rive（画箭头/点按不看棋盘忙不忙）把对局状态机 wedged。现版本画箭头前等棋盘安静 250ms（最多等 1.2 秒兜底），回退反射扫描节流到每秒一次。若还遇到：先别动对局，看 App 状态页 `循环心跳`+ LSPosed 日志 `hb:` 行贴出来 |
| 横幅显示 `局面停滞/x分无新局面` | 不是 bug，是诊断结论：对局 45 秒以上没产生新局面（对局结束/结算画面/切后台最常见）。确认棋盘是否已将死或出现完成界面；若棋还在下但无新局面，把 `content query` 的 `loopAgoSec/posAgoSec/engine` 三列贴出来 |
| 自动走棋点了没反应 | 看三行日志：`riveView pick`（选了哪个 View、多大）→ `tap <格> -> (x,y) ret=…`（`ret=false`=棋盘没收；坐标明显出界=映射偏了）→ `autoplay performed`（没这行就是新鲜度门拦了，看 `moved on`/`no board view` 行） |
| 卡住时点一下自己棋子就恢复 | 旧现象（已修）：对局端状态机被动画中途的绘制/点按 wedged，真实点按把它复位。现版本绘制与点按都等安静时刻；`hb:` 心跳（`pub/dup/ctor/render/fen/fb`，10 秒一行）保留作诊断 |
| 点的格子偏了一格 | `tap` 行坐标 vs 实际选中格：棋盘在视图里不是完全居中时按实测偏移调 `squareToScreen` |
| `Unknown authority com.chessassist.bridge` | 老版本 Provider 桥在 Android 11+ 上必死（包可见性），现版本已改走 socket，不应再出现 |

## 四、架构（v2，现状）

```
多邻国进程（LSPosed）                    伴侣进程
ox5/dm5 构造 + mz6.I()/J() ──► StateBridge ──► FEN ──► BridgeClient ──Socket──► BridgeServer ──► EngineLoop ──► Stockfish
mz6.e0() 画原生箭头 ◄── BridgeClient ◄──Socket── bestmove ◄── EngineLoop ◄── libstockfish.so（NNUE 内嵌）
```

- **传输**：`127.0.0.1:41717` JSON 行协议。Provider 桥已废弃（多邻国看不见我们的 authority），
  仅保留 `content query` 供 adb 诊断。
- **类名映射**：`module/src/main/assets/remap.json` 在**编译期烘进** `RemapTable`
  （`generateRemapTable` 任务）。运行时零 IO——assets 走 ClassLoader 读不到，
  `createPackageContext` 从多邻国调必抛 `NameNotFoundException`（包可见性），两条都已验证走不通。
- **绘制**：所有箭头绘制/清理调用都在宿主主线程（6.105.2 为 `mz6.e0()/c0()`；旧版子线程碰 Rive 必 SIGSEGV，有 tombstone 为证，
  崩溃线程名即 `duo-chess-bridg`）。
- **走棋点按**：Rive 棋盘 View 靠构造直钩发现（`app.rive.runtime.kotlin.RiveAnimationView`，
  dex 实锤），按“大且方、已布局、已显示”打分多选一；`dispatchTouchEvent` 吃的是 View
  **局部坐标**（给屏幕坐标会整体下偏，返回 true 但点出界外，表现为点了没反应）；
  socket 发送与关闭拿同一把锁（错开会在 `socketWrite0` 里 native 崩溃，同样无 Java 栈）。
- **去重**：上报按 FEN 变更（同 FEN 永不重发）；画箭头按 `(fen,move)` 全局去重、不过期；
  新开局（初始 FEN）清掉上局残留的颜色/招法/绘制状态。
  细则：跳过（对方回合）**不**记入去重（颜色滞后修正到达时重判）；上报键是 FEN+走子方+我方
  三元组（同局面颜色修正会重发）；跳过分支每次休眠 200ms（之前空转吃电）；渲染上报节流 200ms。
- **防抖与世代**：对局中钩子触发可达每秒十几次（含几秒 3 个新局面的抖动），伴侣侧新局面
  需存活 250ms 才送分析（抖掉动画/重试中间态，只慢 0.25 秒）；自动走棋每条点按链带世代号，
  局面一切换，没发出的点全作废——交叉开火是之前卡死的直接诱因。实测抖动对局约 4~5 秒一箭，
  无重复、无刷屏。
- **安静落笔**：画箭头前看棋盘安静了 250ms 没有（以钩子触发为准），动画正酣就推迟、
  最多等 1.2 秒——动画中途碰 Rive 是 wedging 头号嫌疑（手动自动都会卡、自动更多，
  因为还多点按）。ViewModel 回退反射扫描节流到每秒一次，不再给 UI 线程加压。
- **颜色**：`getSymbol()` 实测返回大写 `B/W`，FEN 里是小写，边界统一转小写再比。
- **libxposed API 102**：使用官方 `io.github.libxposed:api:102.0.0`（compileOnly），旧 `de.robv.android.xposed` 接口和自制桩已移除；元数据在 `META-INF/xposed/`，只有一个入口。
- **横幅写屏纪律**：第二行颜色是状态的一部分——`showBestMove` 上色，`showThinking`/
  `showStatus`/`clear` 一律复位灰，`正在计算…` 不得带胜率色（B1）。
- **clear 守卫名单**：`推荐/自动走棋中/等待走棋中/ChessPilot/局面停滞` 可替换
  （B2：停滞横幅曾导致对局恢复后仍显示旧文案）。求助（升变/手动走棋）无独立
  保护态——它只在“轮到我且棋盘静止”时出现，而 `clear` 只在对手回合触发、
  停滞标注在我方回合静默，所以自然覆盖不到；新分析到来即正常替换。
- **Fallback 正则无 `^` 锚点**（有锚点时内嵌 FEN 永远命中不了，兜底名存实亡），
  遍历覆盖 `Iterable`（含 Set）与数组（B3，真 Java 引擎验证过新旧两种行为）。
- **生命周期世代号**：`EngineLoop.workerGen` 与 `BridgeServer.serverGen`，快速启停时
  老 worker/accept 线程自动退出，不再出现双引擎进程与重复 bestmove（B4，真机快启停三轮验证）。
- **NNUE**：单 V16 网 `nn-1a298aa575a0.nnue`（98,511,183 字节）INCBIN 编进二进制
  （SF19 起小网退役）。`tools/fetch_stockfish.sh` 带字节数校验，短了就重下——
  之前库里的 10MB 截断文件让引擎启动即崩，查了很久。注意 CDN 的 HEAD
  Content-Length 曾报过错数，以网名即哈希（sha256 前 12 位）为准验货。
- **Stockfish 19**：`sf_19` tag + V16 单网；采用上游 universal 的双命名空间/惰性初始化方案，
  系统 HWCAP 检测后选择 ARMv8 NEON 或 ARMv8.2 DotProd，共享一份网络。NDK 不直接编译 `src/universal/` 中其他平台的入口；
  SF19 对坏 FEN 直接 `CRITICAL ERROR` 杀进程，`StockfishClient` 发前先做结构校验，
  防毒局面 crash-loop 打穿退避。

## 五、多邻国升级怎么办

1. `python tools/remap.py --apk <新包>.apk`（也支持 `.apks`/`.apkm`，需 `pip install androguard==3.3.5`），重写
   `module/src/main/assets/remap.json`，同时更新类名、箭头清理方法和包版本。脚本会核对运行时仍使用的字段/方法；缺失或歧义会报错并保留原文件，不沿用旧混淆名。
   `python tools/remap.py --apk <同一安装包> --check` 可只校验、不写入。
2. 重编 `:app:assembleRelease`（映射会自动烘入合包）→ 同密钥签名 → 安装。API 102 模块可热重载；新版本映射若不适用于当前多邻国，应先换到对应的多邻国版本。
3. 看 LSPosed 日志：`remap table v<新版>` + `hooked ChessGameState`，再确认局面上报、箭头清理和黑白两方走棋方向；
   若出现 `!! ChessGameState not found` 就是映射没对上。

## 五点五、远程算力（电脑下棋，手机看戏）

- 同仓 `pc/` 目录：`pc_engine.py` + 双击启动 `start-pc-engine.bat`。
  电脑跑桌面 SF19（32 线 4G，800ms 干到深度 21），手机只收发招。
- 手机高级设置 → 算力后端：填电脑 IP（如 `192.168.1.230`）→ 测试远程连接
  （回显引擎名/线程/RTT）→ 后端选自动。本机/自动/远程电脑三档，默认本地。
- 自动挡 = 远程优先：连不上、超时、断线，秒切本地接着算（事件记原因），
  15 秒退避 + 下局重连，不用动手。状态页 `后端` 行显示当前是谁在算；
  远程在线时悬浮窗绿框 + `算力` 角标（对标狂暴的红框+`狂暴`，远程优先显示）。
- 时长听谁的：**远程思考时间 / 远程固定深度**两个滑杆随请求发给电脑，
  电脑服从；脚本 `--movetime/--depth` 是默认值；线程/Hash 只能在脚本改
  （要重启进程）。上面三个本地滑杆只管本地引擎。
- 物理限制：同 WiFi；秒回 bot 给不了 ponder/远程时间，无红箭无命中正常。
